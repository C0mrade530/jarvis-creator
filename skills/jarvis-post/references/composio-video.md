# Публикация видео через Composio

Маршруты и схемы проверены 8 ноября 2026 года. Схема активного инструмента определяет поддерживаемые поля и способ загрузки.

## Перед передачей файла

1. Подготовь локальный финальный файл и подпись. Проверь файл через `ffprobe`, размер и параметры площадки. Покажи пользователю файл, текст, обложку при наличии, точный аккаунт или канал, видимость, способ отправки и время с часовым поясом. Если загрузка требует временного внешнего хранилища, укажи его и режим доступа. Для черновика достаточно этого комплекта.
2. Используй собственное активное подключение пользователя. В CLI начни с `composio whoami` и `composio search`. Для нужного действия посмотри `composio execute <slug> --get-schema` и `composio execute <slug> --help`. В подключённом приложении Composio найди операции, проверь соединение и получи полную схему каждого действия в той же сессии. Личный аккаунт и целевой канал подтверждай точечным чтением. `./jarvis connect <площадка>` помогает открыть подключение. [Справка Composio CLI](https://docs.composio.dev/docs/cli)
3. Отправляй в согласованное назначение только выбранный финальный файл. Для поля `file_uploadable` используй загрузчик текущего клиента, который читает именно этот локальный файл. Сначала проверь, что установленный клиент поддерживает такой режим. Если схема ждёт объект с `name`, `mimetype`, `s3key`, передай объект, полученный от штатной загрузки. Абсолютный путь компьютера сам по себе такой объект не создаёт. В SDK разрешай только узкую папку с готовым экспортом согласно документации версии. В размещённом клиенте используй поддерживаемую передачу файла, которой доступен выбранный артефакт. Для поля URL подходит разрешённая прямая ссылка, которую сервер площадки может получить в течение обработки. [Правила загрузки файлов Composio SDK](https://docs.composio.dev/reference/changelog)
4. Получи точное подтверждение комплекта до загрузки или отправки. Если доступный способ передачи меняет видимость файла или формат публикации, покажи это изменение пользователю. При отсутствующем загрузчике или доступе выдай готовый комплект и назови шаг для ручной загрузки.

## Instagram Reels

1. `INSTAGRAM_GET_USER_INFO` помогает сверить подключённый профессиональный профиль и его ID. Для собственного аккаунта схема допускает `ig_user_id` со значением `me`. Для создания используй ID нужного профиля.
2. `INSTAGRAM_POST_IG_USER_MEDIA` создаёт контейнер. Укажи `media_type` со значением `REELS`, утверждённую `caption` и `video_file` из штатной загрузки либо доступный Meta `video_url`. У `video_file` по проверенной схеме создаётся временный публичный URL для чтения Meta. При необходимости передай согласованную обложку через поддерживаемый `cover_url`. Сохрани возвращённый ID контейнера локально.
3. `INSTAGRAM_POST_IG_USER_MEDIA_PUBLISH` принимает `ig_user_id` и `creation_id`. По проверенной схеме он сам ожидает состояние `FINISHED` в пределах `max_wait_seconds`. Используй штатное ожидание обработки для Reels. При таймауте проверь состояние контейнера доступной операцией чтения или сверь публикации профиля до повторной попытки.
4. По возвращённому ID проверь готовый пост через `INSTAGRAM_GET_IG_MEDIA` и возьми `permalink`, если он доступен. Контейнер и опубликованный пост имеют разные ID.

## YouTube

1. `YOUTUBE_LIST_CHANNELS` с `mine` помогает сверить канал подключения. Для категории используй значение пользователя или список через `YOUTUBE_LIST_VIDEO_CATEGORIES`.
2. Для черновика предложи `private` как безопасный вариант. Передавай выбранное и подтверждённое значение `privacyStatus`. Заголовок, описание, категория, теги при необходимости и видимость берутся из согласованного комплекта.
3. `YOUTUBE_MULTIPART_UPLOAD_VIDEO` использует объект файла в `videoFile`. `YOUTUBE_UPLOAD_VIDEO` использует `videoFilePath`, который в проверенной схеме тоже является объектом загруженного файла. Для обоих полей проверь загрузку по текущей схеме. Выбери одну операцию. При неясном результате сначала проверь канал и статус, чтобы избежать дубликата.
4. Сохрани полученный video ID. Проверь обработку и фактическую видимость через `YOUTUBE_GET_VIDEO_DETAILS_BATCH` с доступными частями `status` и `processingDetails`. Если проверка недоступна, сообщи статус приёма файла отдельно от готовности видео к просмотру.

## Telegram

1. Подключение использует собственного бота пользователя. Его ключ вводится в интерфейсе подключения Composio. `TELEGRAM_GET_ME` возвращает ID бота, `TELEGRAM_GET_CHAT` сверяет канал по `chat_id`, `TELEGRAM_GET_CHAT_MEMBER` позволяет проверить роль бота и право публикации в канале.
2. Для видео с плеером нужна операция Telegram Bot API `sendVideo`. Снова проверь каталог активного клиента. В проверенном каталоге Composio доступна `TELEGRAM_SEND_DOCUMENT`, а отдельной операции `sendVideo` в нём нет. Поле `document` в проверенной схеме строковое. По описанию инструмента загрузка по URL ограничена PDF и ZIP. Для варианта «файл документа» согласуй его отдельно и используй поддерживаемый текущей схемой способ, например подходящий `file_id` этого бота. [Каталог Telegram в Composio](https://docs.composio.dev/toolkits/telegram)
3. Если активный клиент подтверждает `sendVideo` и передачу MP4, проверь схему и выполни одобренную отправку с `chat_id`, файлом и подписью. Если этот маршрут недоступен, передай пользователю готовый MP4 и подпись для загрузки в нужный канал через Telegram с выбранным режимом видео. [Telegram Bot API sendVideo](https://core.telegram.org/bots/api#sendvideo)
4. Фиксируй успешную отправку по возвращённым `chat.id` и `message_id` или по видимой публикации в целевом канале. При таймауте проверь наличие публикации в канале до повтора.
